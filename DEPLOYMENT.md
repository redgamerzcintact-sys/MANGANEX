# MANGANEX — Free Prototype Deployment

This repository uses a split deployment:

- Frontend: Cloudflare Pages (React + Vite)
- API: Render free Python web service (FastAPI)
- Database: SQLite for temporary demo data only

The frontend currently calls the FastAPI service through `VITE_API_BASE_URL` (see `src/services/api.ts`). The Java backend is not currently used by this frontend and is not part of this deployment.

## 1. Deploy the API on Render

1. Sign in to Render and connect the private GitHub repository `redgamerzcintact-sys/MANGANEX`.
2. Choose **New → Blueprint** and select this repository.
3. Render reads the root-level `render.yaml`. Review the service settings and create the service.
4. When prompted for `BACKEND_CORS_ORIGINS`, enter the exact Cloudflare Pages origin after creating the Pages project, for example:
   `https://manganex.pages.dev`
   Do not include a path or trailing slash.
5. Wait for the service to finish deploying.
6. Copy its public Render URL, for example `https://manganex-api.onrender.com`.
7. Check `https://YOUR-RENDER-SERVICE.onrender.com/health`. It should return JSON with status `HEALTHY` and database `CONNECTED`.

The Blueprint generates `SECRET_KEY` automatically. Keep it in Render; never commit it or paste it into frontend variables.

## 2. Deploy the frontend on Cloudflare Pages

1. In Cloudflare, open **Workers & Pages → Create application → Pages → Connect to Git**.
2. Select `redgamerzcintact-sys/MANGANEX` and the `main` branch.
3. Set the build configuration:
   - Framework preset: **React (Vite)**
   - Root directory: `/` (repository root)
   - Build command: `npm run build`
   - Build output directory: `dist`
4. Before the first production build, add this Pages build environment variable:
   - Name: `VITE_API_BASE_URL`
   - Value: `https://YOUR-RENDER-SERVICE.onrender.com/api/v1`
5. Save and deploy. Choose the Pages project name `manganex` if available; its URL will then be `https://manganex.pages.dev`. If that name is unavailable, use the actual assigned `*.pages.dev` URL in the CORS setting on Render.
6. After the first deploy, confirm the site loads at its assigned `https://<project>.pages.dev` address.

## 3. Confirm CORS

In Render → `manganex-api` → Environment, confirm:

- `BACKEND_CORS_ORIGINS` = exact Pages origin, e.g. `https://manganex.pages.dev`
- `ENVIRONMENT` = `production`
- `DEBUG` = `false`
- `ALLOW_DEMO_AUTH_TOKENS` = `false`
- `SECRET_KEY` exists and is generated by Render

If you change the Pages project name, update `BACKEND_CORS_ORIGINS` to the new origin and redeploy the API.

## 4. Verify the live app

1. Open `https://YOUR-RENDER-SERVICE.onrender.com/health` and check for `HEALTHY`.
2. Open the Pages site and test login, registration, mine list, geology, production, satellite, and Nexus AI screens.
3. Open browser DevTools → Network/Console. API calls should go to the Render URL, not `127.0.0.1` or `localhost`.
4. A first API request after inactivity can take around a minute because Render free services sleep after 15 minutes without traffic.

## Prototype limitations and security

- Render free web services have an ephemeral filesystem. SQLite data and uploaded local files can disappear on service restarts, redeploys, or sleep/wake cycles. Do not use this setup for real user or operational data.
- Render's free web services can sleep after 15 minutes of inactivity and take about a minute to wake.
- The free Render PostgreSQL offering expires after 30 days; it is not configured here.
- Keep the GitHub repository private. Cloudflare Pages and Render can connect to a private repository after you authorize their GitHub integrations.
- Rotate/revoke any previously exposed Google Maps API key, JWT secrets, and demo passwords. Put only public, domain-restricted browser keys in frontend build variables. Never place backend secrets in `VITE_*` variables.
- The backend currently defaults to synthetic demo data. Treat all displayed predictions and analytics as prototype outputs, not validated mining or regulatory advice.
- The Java backend is intentionally not deployed in this phase; the current frontend API client targets FastAPI.
